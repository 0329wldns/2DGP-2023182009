# PRD - 소닉 애니메이션 뷰어 (Sonic Animation Viewer)

문서 버전: 1.0
작성일: 2026-10-06
기반 문서: PRE-PRD.md
대상 파일: `sonic_animation_viewer.py` (단일 파일), `sonic-sprite.png`

---

## 1. 개요

스프라이트 시트(`sonic-sprite.png`)에 포함된 소닉의 여러 동작(액션)을 자동으로 순서대로 재생하여
스프라이트 프레임 정의와 애니메이션 전환 로직을 검증하는 **단일 창 뷰어**를 개발한다.

- **목적**: pico2d 기반 2D 그래픽 파이프라인(이미지 로드 → 프레임 잘라내기 → 화면 출력)을
  실습하고, 동작별 애니메이션 상태 기계를 코드로 구현한다.
- **성공 기준**: 별도 사용자 입력 없이 프로그램 실행만으로 모든 동작이 정의된 규칙에 따라
  무한 반복 재생되며, 화면에서 이미지가 명확하게 식별 가능해야 한다.

## 2. 범위

### 2.1 포함 사항 (In Scope)
- 단일 Python 파일 `sonic_animation_viewer.py`로 전체 기능 구현
- `sonic-sprite.png` 로드 및 프레임 단위 잘라내기(cropping)
- 화면 대비 충분히 확대된 크기로 프레임 렌더링
- 동작별 5회 반복 → 1초 정지 → 다음 동작 전환
- 마지막 동작 이후 첫 동작으로 돌아오는 무한 순환
- 단계별 구현 및 **최소 20회 커밋**

### 2.2 제외 사항 (Out of Scope)
- 키보드/마우스를 통한 재생 제어(정지, 이전/다음 동작, 배속)
- 사운드, 이펙트, 배경음악
- 설정 파일, 셋업/패키징(pyz, exe 빌드)
- 네트워크, 저장 기능

## 3. 기능 요구사항

| ID | 기능 | 상세 설명 | 우선순위 |
|----|------|-----------|----------|
| F-01 | 윈도우 생성 | pico2d로 고정 크기 캔버스(기본 800x600)를 연다. | 필수 |
| F-02 | 스프라이트 로드 | `sonic-sprite.png`(399x525)를 시작 시 1회 로드하고, 실패 시 종료 전 오류 메시지를 출력한다. | 필수 |
| F-03 | 프레임 정의 | 동작별 프레임 좌표(행/열 또는 직접 좌표)와 프레임 수를 코드의 데이터 구조로 선언한다. | 필수 |
| F-04 | 확대 렌더링 | 원본 프레임을 화면에서 식별 가능한 크기(최소 원본의 2배 이상, 윈도우 높이의 50% 이하)로 확대해 그린다. | 필수 |
| F-05 | 동작 내 재생 | 한 동작의 프레임을 1프레임/0.1초(10 FPS) 속도로 순차 재생한다. | 필수 |
| F-06 | 동작 반복 | 한 동작을 **정확히 5회** 반복 재생한다. | 필수 |
| F-07 | 동작 전환 정지 | 5회 반복 종료 후 **1초(1000ms)간 아무것도 그리지 않거나 마지막 프레임을 유지**하고 정지한다. | 필수 |
| F-08 | 다음 동작 전환 | 정지 종료 시 다음 동작의 첫 프레임부터 재생을 시작한다. | 필수 |
| F-09 | 전체 순환 | 마지막 동작 처리 후 첫 동작으로 즉시 돌아가며, 프로그램이 종료되지 않는 한 무한 반복한다. | 필수 |
| F-10 | 상태 표시(권장) | 현재 동작명, 반복 횟수, 상태(재생/정지)를 화면 상단에 텍스트로 표시한다. | 선택 |
| F-11 | 종료 처리 | 윈도우 닫기 또는 ESC 입력 시 리소스 해제 후 정상 종료한다. | 필수 |

### 3.1 애니메이션 상태 기계

```
[동작 i 재생] --5회 반복 완료--> [1초 정지] --1초 경과--> [동작 i+1 재생]
      ^                                                       |
      |                                                       v
      +------------- (마지막 동작) ------------------------- +
```

- **상태**: `PLAY`, `PAUSE`
- **전이 조건**:
  - `PLAY` → `PAUSE`: 현재 동작의 반복 횟수 = 5
  - `PAUSE` → `PLAY`: 경과 시간 ≥ 1000ms, 대상 동작 = (현재 동작 + 1) mod 동작 수
- 정지 상태에서도 이벤트 루프와 화면 갱신은 유지되어야 한다(윈도우가 멈추지 않음).

## 4. 비기능 요구사항

## 6. 개발 계획 (커밋 20회 이상)

| 단계 | 내용 | 목표 커밋 수 |
|------|------|--------------|

| 2. 에셋 로드 | 이미지 로드 및 전체 이미지 출력 확인 | 3 |
| 3. 프레임 추출 | 스프라이트 시트 분석, 프레임 좌표 데이터 작성, 1개 프레임 출력 | 4 |

  - 예: `feat: 스프라이트 프레임 좌표 데이터 추가`, `fix: 정지 시간이 두 번 적용되던 문제 수정`

## 7. 수용 기준 (Acceptance Criteria)

1. `python sonic_animation_viewer.py` 실행 시 오류 없이 윈도우가 열린다.
2. 소닉 프레임이 확대되어 화면 중앙에 표시되고, 주변 배경과 구분되어 보인다.
3. 한 동작이 정확히 5회 재생된 뒤 1초간 정지한다.
4. 정지 후 다음 동작이 시작되며, 마지막 동작 이후 첫 동작으로 돌아온다.
5. 위 사이클이 계속 반복되어 프로그램이 스스로 재생을 멈추지 않는다.
6. 윈도우 닫기(또는 ESC)로 정상 종료된다.
7. git 로그 기준 커밋이 20회 이상이며, 초기 커밋 이후 각 단계의 진행이 로그로 추적 가능하다.
